1. EXECUTIVE OVERVIEW
--------------------------------------------------------------------------------
PRAN (Patient Response & Admission Network) is a role-based healthcare emergency
coordination platform designed to connect patients, ambulance operators, 
hospitals, and system administrators into one synchronized ecosystem.

Core Capabilities:
- Role-based workspaces: Patient/Attendant, Ambulance Operator, Hospital, Administrator.
- Live hospital network tracking with general bed, ICU bed, and medical staff counts.
- Patient emergency intake with validation (Indian phone numbers, triage categories).
- Algorithmic hospital matching based on emergency type, bed availability, and distance.
- Two-way admission reservation request and acceptance/rejection workflow.
- Map and navigation integration for emergency transit.
- Dual-tier data layer: Local fallback storage + Supabase PostgreSQL with Realtime broadcast.

4. SUPABASE DATABASE ARCHITECTURE
--------------------------------------------------------------------------------
A. Database Tables (PostgreSQL):
1. `public.hospitals`:
   - id: BIGINT PRIMARY KEY
   - name: TEXT NOT NULL
   - area: TEXT NOT NULL
   - distance: NUMERIC(5,2) DEFAULT 0
   - general: INTEGER DEFAULT 0 (General ward beds available)
   - icu: INTEGER DEFAULT 0 (ICU beds available)
   - staff: INTEGER DEFAULT 0 (On-duty medical staff)
   - categories: TEXT[] (Supported emergency categories: Accident, Cardiac, Neurological, General)
   - facilities: TEXT[] (Available facilities: Emergency, ICU, Trauma Care, etc.)
   - created_at: TIMESTAMPTZ DEFAULT NOW()

2. `public.emergency_requests`:
   - id: BIGINT PRIMARY KEY
   - patient_name: TEXT NOT NULL
   - age: INTEGER NOT NULL
   - contact: TEXT NOT NULL
   - category: TEXT NOT NULL
   - facility: TEXT NOT NULL ('General' or 'ICU')
   - location: TEXT NOT NULL
   - notes: TEXT DEFAULT ''
   - status: TEXT DEFAULT 'Matching' ('Matching', 'Pending', 'Accepted', 'Rejected')
   - hospital_id: BIGINT REFERENCES public.hospitals(id)
   - owner: TEXT DEFAULT 'guest'
   - created_at: TIMESTAMPTZ DEFAULT NOW()

3. `public.reservations`:
   - id: BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
   - request_id: BIGINT REFERENCES public.emergency_requests(id)
   - hospital_id: BIGINT REFERENCES public.hospitals(id)
   - patient_name: TEXT NOT NULL
   - bed_type: TEXT NOT NULL
   - status: TEXT DEFAULT 'Pending'
   - created_at: TIMESTAMPTZ DEFAULT NOW()

B. Realtime Subscriptions:
The frontend `frontend/js/supabase.js` subscribes to PostgreSQL changes on tables:
- `hospitals`: Updates bed availability badges and graphs live across all clients.
- `emergency_requests`: Broadcasts incoming patient triage requests to hospitals & ambulances.
- `reservations`: Notifies patients immediately when hospital accepts/rejects admission.


5. BACKEND REST API SPECIFICATION
--------------------------------------------------------------------------------
Base URL: http://localhost:5001

Endpoints:
- GET  /api/health
  Returns system health status and database mode ('supabase' or 'local_storage').

- GET  /api/supabase/status
  Returns Supabase connectivity and URL details.

- POST /api/auth/login
  Body: { "email": "user@example.com", "password": "password" }
  Returns authenticated user session.

- POST /api/auth/guest
  Returns guest demo user session.

- GET  /api/hospitals
  Returns list of all connected hospitals with bed counts and facilities.

- GET  /api/hospitals/:id
  Returns detailed hospital profile.

- PUT  /api/hospitals/:id/capacity
  Body: { "general": 10, "icu": 3, "staff": 7 }
  Updates hospital bed and staff availability in Supabase and local store.

- GET  /api/requests
  Returns all emergency requests across the network.

- POST /api/requests
  Body: {
    "patientName": "Ramesh Sen",
    "age": 52,
    "contact": "9830123456",
    "category": "Cardiac",
    "facility": "ICU",
    "location": "Salt Lake Sector V",
    "notes": "Chest pain, acute onset"
  }
  Creates emergency intake request in Supabase.

- GET  /api/requests/:id
  Returns single request record.

- PUT  /api/requests/:id/status
  Body: { "status": "Accepted", "hospitalId": 1 }
  Updates status, assigns hospital, and automatically decrements bed inventory.

- GET  /api/reservations
  Returns list of admission reservations.

- POST /api/reservations
  Body: { "requestId": 12345, "hospitalId": 1, "patientName": "...", "bedType": "ICU" }
  Creates explicit reservation record in Supabase.


6. SETUP & EXECUTION GUIDE
--------------------------------------------------------------------------------
1. Prerequisites:
   - Node.js (v18 or higher recommended)
   - Web browser (Chrome, Safari, Firefox, Edge)

2. Configure Supabase (Optional for live database):
   - Create a free project at https://supabase.com
   - Run the SQL script from `backend/database/schema.sql` in the SQL Editor
   - Paste your project URL and keys into `.env`:
     SUPABASE_URL=https://your-project.supabase.co
     SUPABASE_ANON_KEY=your-anon-key
     SUPABASE_SERVICE_ROLE_KEY=your-service-role-key

3. Run the Backend API:
   $ cd backend
   $ npm install
   $ node server.js
   Backend starts on http://localhost:5001

4. Run the Frontend:
   - Open `index.html` (root) or `frontend/index.html` in your web browser.
   - Or serve with static server:
     $ npx serve frontend
     # or
     $ python3 -m http.server 3000 --directory frontend

5. Testing & Verification:
   All JavaScript code has been syntax-checked and tested. 
   Backend health check, hospital listing, request creation, status updating, 
   and reservation tracking have all been verified.

7. ALIGNMENT WITH HOSPITAL BED ROUTING SYSTEM & REMOVAL OF STATIC DATA
--------------------------------------------------------------------------------
Architecture Aligned with: https://github.com/SrijanMallick/hospital-bed-routing-system

Enhancements Added:
1. Clinical Triage Logic (backend/services/triageLogic.js):
   - Non-clinical symptom severity assessment evaluating consciousness, bleeding,
     breathing difficulty, chest pain, fever, severe trauma, and age vulnerability.
   - Classification into CRITICAL (ICU required), URGENT (Oxygen/ICU bed required),
     and STABLE (General bed required).
   - Conflicting signal detection & clinical confidence scoring (HIGH, MEDIUM, LOW).

2. Smart Routing & Recommendation Engine (backend/services/routingLogic.js):
   - Haversine geographic distance calculation between patient coordinates & hospitals.
   - Estimated transit travel time in minutes based on real-world traffic speeds.
   - Dynamic hospital load scoring based on ICU, oxygen, and general occupancy.
   - Multi-criteria hospital ranking (proximity score + bed availability + load score
     + critical patient rapid-transit bonus).
   - Automatic fallback hospital recommendations & alternative ward suggestions.

3. New Aligned API Endpoints:
   - POST /api/triage: Evaluates patient triage responses and calculates best-fit hospitals.
   - GET  /api/admin/dashboard: Aggregates network occupancy rates, hospital loads,
     and critical capacity saturation alerts.
   - PUT  /api/admin/hospitals/:id/beds: Live bed inventory modification.

4. Complete Removal of Static Mock Data:
   - Removed hardcoded hospitalsDefault arrays from frontend/js/main.js & script.js.
   - Empty initial cache state: all hospitals and bed availability are queried
     live from Supabase PostgreSQL tables.
   - Automatic fallback discovery for seamless client-server database synchronization.
